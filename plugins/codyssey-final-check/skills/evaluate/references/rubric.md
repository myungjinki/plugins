# 붙임2 코디세이 AI 네이티브 파이널 프로젝트 평가기준표

## 1단계: 필수요건 게이트(G1~G7)

○ (판정원칙) 7개 요건 전부 충족 시 PASS, 미충족 시 보완 요청

**< 필수 요건 게이트 >**

| 번호 | 요건 | 확인 방법 |
|---|---|---|
| G1 | 저장소에 기획서, 기능 요구 명세서(시스템 아키텍처 포함), README(필수 5개 항목 포함) 문서가 명확하게 작성되어 있고, 문서 간 모순 없음 | 저장소 문서 대조 |
| G2 | 외부 서비스 접속이 가능하게 배포되어 있고, 모든 기능이 에러·비정상 종료 없이 구동 | 안내된 방법으로 접속 후 확인 |
| G3 | 생성형 AI 또는 AI Agent가 핵심 기능으로 포함되며, 필수 기술 요소 중 2개 이상을 인정 수준으로 구현 | AI 활용 명세 및 구동 확인 |
| G4 | 기능 요구 명세서에 명시한 필수(Must) 기능 전부 동작 | 명세서 구현현황 표와 구동 대조 |
| G5 | 실사용자 5명 이상에게 서비스를 제공하고 피드백 수집 | 사용자 피드백 기록 확인 |
| G6 | GitHub에 소스·문서 업로드, 버전 관리 이력 및 모든 팀원의 실질적 기여 기록 존재 | README 역할표, 커밋 이력 |
| G7 | 1. AI 생성 콘텐츠임을 사용자에게 명시<br>2. 개인정보 수집 시 동의 확보<br>3. 테스터 개인정보 저장소 비노출 | 서비스 화면·동의 절차 |

○ (G3 인정 수준) 단순 API 호출은 불인정, 요소별 인정 기준은 기준 표 참조

**< 기술 요소별 인정·불인정 기준 >**

| 기술 요소 | 인정 기준 | 불인정 기준 |
|---|---|---|
| AI Agent | LLM이 2개 이상의 도구·함수 중 호출 대상을 스스로 정하거나, 계획 → 실행을 여러 단계로 반복 | 프롬프트 1회 → 응답 출력 |
| RAG | 질의마다 외부 문서·DB를 검색해 결과를 프롬프트에 활용 | 고정 텍스트를 프롬프트에 붙임 |
| 멀티모달 AI | 이미지·음성·영상을 모델이 입력으로 해석하거나 출력으로 생성 | 파일 업로드·저장만 하고 모델은 텍스트만 처리 |
| 자동화 워크플로우 | 일정 또는 이벤트로 시작해 2개 이상의 서비스가 사람의 개입 없이 이어짐 | 버튼 클릭 → API 1회 호출 |
| Long-term Memory | 세션이 끝난 뒤에도 사용자별 정보가 저장되어 다음 세션의 응답에 반영 | 한 세션 안의 대화 이력 유지 |

○ (G4 동작 기준) 기능별 3회 시도 중 2회 이상 기대 결과가 나오면 충족으로 인정
- Must 기능에 G3 인정 기술 요소 2개가 쓰인 기능 포함 필요
- 필수 기능을 최소로 잡아 통과한 경우 PASS 유지, 2단계 영역 1에서 감점

○ (G5 실사용자 범위) 팀원 제외, 타 교육생은 서비스 타깃 해당 시에만 인정

○ (판정 구분) 요건별로 충족·추가 요청·미충족 3가지로 판정

| 구분 | 판정 기준 | 처리 |
|---|---|---|
| 충족 | 요건 만족 | - |
| 추가요청 | 존재 여부만 확인하면 되는 누락(팀원 기여 기록, AI 생성 콘텐츠 표기 문구, 문서 위치·파일 형식, 피드백 기록의 타깃 해당 근거·가명 처리) | 추가 자료 요청 및 확인 후 평가 정상 진행 |
| 미충족 | 접속·구동 불가, 기술 요소 미달, Must 기능 미동작, 테스터 5명 미달, 문서 부재, 버전 관리 이력 없음, 개인정보 동의 절차 없음 등에 해당하는 경우 | 미충족 항목과 사유 통보, 수정 후 재평가 진행 |

## 2단계: 루브릭 평가 세부기준 (100점)

○ (대상 및 용도) PASS 팀 대상으로 우수팀 선정을 위한 점수화 단계

○ (배점구성) 6개 영역 100점 구성, 영역별 5단계 등급 판정

**< 루브릭 영역별 배점 >**

| 영역 | 배점 | 주요 평가 내용 |
|---|---|---|
| 1. 문제 정의와 기획 | 20 | 타깃·문제 정의와 근거, 문제→기능→유저 플로우 전개, 필수 기능 범위 적정성 |
| 2. AI 활용 | 30 | AI 결합 방식(단순 API 호출 초과 여부), 기법 적용 근거, 기술 스택 선정 이유 |
| 3. 구현 완성도 | 20 | 코드 구조·컨벤션·예외 처리, 아키텍처와 구현 일치, 실행·사용 가이드 |
| 4. 사용자 피드백 | 15 | 피드백 수집 설계, 분석 및 개선 반영 과정 |
| 5. 협업 체계 | 10 | 역할 분담·균형, Git 이력·진행 문서 기반 협업 증빙 |
| 6. 발표자료 | 5 | 문제 정의·해결 과정·AI 활용 근거·피드백 개선의 구조화 |
| 합계 | 100 | |

○ (산정방식) 영역별 5단계 등급(탁월/우수/양호/보통/미흡)을 매기고, 등급 환산율(100/90/80/70/50%)을 배점에 적용
- 영역 점수 = 배점 × 등급 환산율
- 각 영역별 등급 서술을 모두 충족 시 해당 등급 부여
- 탁월 = 우수 서술 모두 충족 + 영역별 탁월 조건 충족

○ (동점처리) AI 활용 → 문제 정의와 기획 → 구현완성도 → 사용자 피드백 → 협업체계 → 발표 자료 순으로 영역 점수 비교

○ (영역별 등급 기준) 아래 6개 표 적용

**< 영역 1. 문제 정의와 기획 (20점) >**

| 등급 | 판정 기준 |
|---|---|
| 탁월 | 우수 기준 전부 충족 + 근거가 팀이 직접 수집한 자료(인터뷰·설문 등)이고 Must 기능 선정 이유로 연결됨 |
| 우수 | 타깃·문제가 구체적이고 근거(인터뷰·데이터·기존 서비스 비교)와 차별점이 분명하며, 문제→기능→유저 플로우가 끊김 없고 필수 기능 범위가 핵심 가치를 구현하기에 충분함 |
| 양호 | 문제·근거는 명확하나 차별점이나 전개가 일부 약하거나 범위가 다소 과소·과다함 |
| 보통 | 타깃·문제는 정의되었으나 근거가 일반론이거나 기능과의 연결이 약함 |
| 미흡 | 문제가 모호하거나 기능 나열에 그치고, 필수 기능이 핵심 가치 구현에 현저히 부족함 |

※ 필수 기능을 최소로 잡아 통과한 경우, 영역 1 등급 한 단계 하향

**< 영역 2. AI 활용 (30점) >**

| 등급 | 판정 기준 |
|---|---|
| 탁월 | 우수 기준 전부 충족 + 평가자가 기능 요구사항 표에 없는 입력을 1건 넣어도 AI가 서비스 목적에 맞게 동작함 |
| 우수 | AI가 문제 해결의 핵심 단계에 필요한 형태(Agent 도구 호출·RAG·메모리 등)로 결합되어 있고, 기법과 스택의 선택 이유가 문서화됨 |
| 양호 | 결합은 우수와 같으나 선택 이유가 일반적이거나 적혀 있지 않음 |
| 보통 | 기술 요소 2개를 구현했으나 대부분 API 호출 후 출력 전달 수준임 |
| 미흡 | 기술 요소가 없어도 Must 기능이 성립함 |

**< 영역 3. 구현 완성도 (20점) >**

| 등급 | 판정 기준 |
|---|---|
| 탁월 | 우수 기준 전부 충족 + 평가자가 시도한 잘못된 입력 2건 모두에서 서비스가 멈추지 않고 안내를 보여 줌 |
| 우수 | 모듈 분리·일관된 컨벤션·예외 처리가 전반에 적용되고, 아키텍처 문서가 구현과 일치하며 README만으로 처음 접속한 사용자가 핵심 시나리오를 완료할 수 있음 |
| 양호 | 대부분 일관되고 일치하나 예외 처리나 문서가 일부 부족함 |
| 보통 | 동작에는 문제가 없으나 구조·컨벤션이 일관되지 않거나 문서와 구현이 일부 다름 |
| 미흡 | 구조 없이 뒤섞여 가독성이 낮음 |

**< 영역 4. 사용자 피드백 (15점) >**

| 등급 | 판정 기준 |
|---|---|
| 탁월 | 우수 기준 전부 충족 + 테스터가 10명 이상이거나, 개선 후 같은 대상에게 다시 확인한 기록이 있음 |
| 우수 | 대상·질문을 설계해 체계적으로 기록하고, 피드백을 분류·우선순위화해 개선 항목을 정하며 반영 전후(커밋·화면)를 확인할 수 있고 미반영 이유도 설명함 |
| 양호 | 주요 피드백이 개선으로 연결되고 반영 근거(커밋·화면)가 있음 |
| 보통 | 피드백 일부가 반영되었으나 결과 확인이 어렵거나 선택 근거가 없음 |
| 미흡 | 수집만 있고 개선 반영이 없거나 확인할 수 없음 |

**< 영역 5. 협업 체계 (10점) >**

| 등급 | 판정 기준 |
