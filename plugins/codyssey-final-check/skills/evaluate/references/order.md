# 점검 순서 안내

아직 점검하지 않았습니다. 아래 순서대로 입력해 주세요. 한 번에 전체를 점검하려면 `all`을 입력합니다.

| 순서 | 입력 | 직접 확인할 것 |
|---|---|---|
| 1 | `G2 G7` | 실제 접속, 전체 기능 구동, 화면 표기 |
| 2 | `G3 G4` | AI 실제 동작, 기능별 3회 중 2회 |
| 3 | `G5` | 없음 |
| 4 | `G1` | README 필수 5개 항목 |
| 5 | `G6` | 없음 |
| 6 | `all` | 앞에서 확인한 것 중 바뀐 것 |

## 이 순서인 이유

1. **`G2 G7`:** 접속이 안 되면 G3·G4의 구동도 확인할 수 없습니다. G7 화면 표기도 접속할 때 함께 봅니다.
2. **`G3 G4`:** 미달이면 코드까지 고쳐야 해 비용이 가장 큽니다. Must 기능에 G3 인정 요소 2개가 쓰여야 해서 함께 보고, G3와 이어진 영역 2는 배점도 30점으로 가장 큽니다.
3. **`G5`:** 테스터 기록이 바뀌면 문서도 바뀔 수 있어 G1보다 먼저 봅니다.
4. **`G1`:** 앞 단계에서 바뀐 내용까지 문서에 한 번에 맞춘 뒤 점검합니다.
5. **`G6`:** 수정 커밋이 쌓일수록 이력이 바뀌므로 요건 중 마지막에 봅니다.
6. **`all`:** 제출 전 최종 확인입니다. 영역 6까지 채점해 100점 합계가 나옵니다.

## 알아 둘 점

- 평가기준표에 정해진 순서는 없습니다. 고치는 비용과 요건 간 관계로 정리한 비공식 권장 순서입니다.
- 구현을 어느 정도 마친 저장소를 점검하는 순서이고, 만드는 순서가 아닙니다.
- 이미 받은 요건은 고친 뒤에만 다시 받으면 됩니다.
- 이 스킬은 서비스에 접속하지 않으므로, 직접 확인할 것은 팀이 확인합니다.

입력 예: Claude `/codyssey-final-check:evaluate G2 G7`, Codex `$evaluate G2 G7`
