# codyssey-final-check

코디세이 AI 네이티브 파이널 프로젝트 저장소를 평가기준표에 맞춰 자가 점검한다.

## 설치

Claude Code:

```bash
claude plugin marketplace add myungjinki/plugins
```

```bash
claude plugin install codyssey-final-check@plugins
```

Codex:

```bash
codex plugin marketplace add myungjinki/plugins
```

```bash
codex plugin add codyssey-final-check@plugins
```

## 사용법

Claude `/codyssey-final-check:evaluate 중간`, Codex `$evaluate 중간`처럼 부른다.

점검할 프로젝트 저장소에서 부른다. 결과 파일 하나만 만들고 다른 파일은 고치지 않는다.

| 입력 | 하는 일 | 상태 |
| --- | --- | --- |
| `쉬움` | 저장소에서 필수요건 G1~G7을 점검한다 | 사용 가능 |
| `중간` | 쉬움에 더해 6개 영역 100점을 채점하고 점수를 올릴 일을 알려 준다 | 사용 가능 |
| `G1`~`G7` | 적은 요건만 점검한다. 예: `G3`, `G2 G5` | 사용 가능 |
| `서비스 검증` | 배포된 서비스에 접속해 기준표대로 시험한다 | 준비 중 |

## 알아 둘 점

- 결과는 자가 점검이며 공식 평가 결과가 아니다.
- 필수요건 결과는 요건별 표로 터미널에 바로 보여 준다.
- 결과는 `docs/evaluate-result/20261106-094720.md`처럼 날짜-시간 이름으로도 저장한다. 커밋은 하지 않는다.
- 결과 파일에는 키가 든 파일의 위치가 적힐 수 있다. 공개 저장소에 올리기 전에 확인한다.
- 서비스를 실행하지 않으므로 G2 접속·구동, G4 동작, G7 화면 표기는 팀이 직접 확인해야 한다.
- 영역 2·3의 탁월 조건은 서비스를 시험해야 하므로 우수까지만 준다.
- 저장소에 API 키가 있으면 파일 위치만 알려 주고 키 값은 출력하지 않는다.

## 필수요건과 루브릭 영역

요건을 고치면 어느 점수와 관련되는지 볼 때 쓰는 비공식 참고 자료다. 평가기준표에 대응표는 없고, 내용을 비교해 정리했다. 명시된 연결은 G4와 영역 1뿐이다. 스킬은 이 표로 채점하지 않으며, 등급은 영역별 서술로 따로 정한다.

| 요건 | 관련 영역 | 이유 |
| --- | --- | --- |
| G1 문서 | 1. 문제 정의와 기획, 3. 구현 완성도 | 기획서는 문제 정의와 기획, 아키텍처 문서와 README는 구현 완성도와 이어진다 |
| G2 배포·구동 | 3. 구현 완성도 | 구동 여부와 실행·사용 가이드가 구현 완성도와 이어진다 |
| G3 AI 기술 | 2. AI 활용 | 같은 기술 요소를 G3는 인정 여부로, 영역 2는 결합 수준으로 본다 |
| G4 Must 기능 | 1. 문제 정의와 기획(명시), 3. 구현 완성도 | 필수 기능을 최소로 잡으면 영역 1 등급이 한 단계 내려간다. 기능 구현은 영역 3과 이어진다 |
| G5 실사용자 | 4. 사용자 피드백 | G5는 테스터 수와 수집 여부를, 영역 4는 분석과 개선 반영을 본다 |
| G6 협업 기록 | 5. 협업 체계 | 같은 역할표와 Git 이력을 G6는 기여 여부로, 영역 5는 균형과 협업 흐름으로 본다 |
| G7 표기·개인정보 | 없음 | 점수 항목이 없고 통과 여부만 가린다 |

- 영역 6 발표 자료는 대응하는 요건이 없다.
- 영역 3의 비밀 정보 감점은 API 키 노출 규칙이라 G7과 별개다. G7-3은 테스터 개인정보를 다룬다.
